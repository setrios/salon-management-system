### 1.3 The curl section — F14

Every `bash` block of "Checking endpoints with curl" was extracted from the
README and run in order against the clean server.

**First run: it failed.** Only the authentication and public reads answered as
commented; from the availability read on, every request answered `404`, `400`
or `VALIDATION_ERROR`. Two causes:

| # | Cause |
|---|---|
| F14a | the section assumed an installation that already had a master with services, prices and working hours — written in lab 5 against a populated development database; a fresh installation has none |
| F14b | it booked on a fixed date, `DATE=2026-11-16`, which had passed |

**Correction** (`0811d23`): the section now creates what it uses — a master, a
service, a price and seven days of working hours, through the same operations
the dashboard uses — books a week ahead (`DATE` computed with `node`), and
creates its own material. A random suffix keeps the names unique so it can be
run again (a first version used `date +%s`; two runs within one second
collided — found by running it twice).
