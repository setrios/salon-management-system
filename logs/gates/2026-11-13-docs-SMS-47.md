## 3. The sample is evidence, not decoration

The ten records are chosen to show the four things the logging deliverable is
about, and every one of them is visible in the file:

1. **the level mapping** — `info` for 200/201, `warn` for 401/404/405/422;
2. **the path rule** — `{appointmentId}` and `{token}` templates instead of the
   concrete values, `/health` outside the contract, and a raw path for a route
   the contract does not define;
3. **the trace id** — present on every record, and the same value the `Problem`
   body carries;
4. **the timing** — `durationMs` per request, so a slow operation is visible
   without a profiler.

The regeneration command is in the sample's README; the script is git-ignored with
the rest of `logs/runtime/`, which is why the sample itself is committed.

## 4. What was not added

- **No screenshot, diagram or prose about the UI.** The repository is the API;
  SMS-36/SMS-37 are outside it.
- **No invented log lines.** A sample with a mock `error` record would document a
  shape the code does not write.
- **No claim that the sample is complete.** §4 of `logs/samples/README.md` lists
  what the run does not produce (a 5xx, the process's own lifecycle events).
