## 1. Why it is a defect

R11 inserts a `master_services` row whose `service_id` is a foreign key. SMS-71
added the check for `masterId`; `serviceId` is still unchecked, so an id that
names no service reaches the database, the foreign key fails, and the error
handler answers 500 — the answer `error-handler.ts` reserves for defects ("500
is never used for a client-caused condition"). R11 declares 422.

The code is not a new decision: at the SMS-71 TEST-GATE the developer chose
**422 `BUSINESS_RULE_VIOLATION`** for an R11 reference that names nothing
(`logs/gates/2026-11-26-test-S6-corrections.md` §6). K6 applies the same answer
to the second reference.

## 2. The tests

| K7 | R11, existing master and service | 201 | 201 (guard: the check must not refuse a valid pair) |

## 3. Planned fix

`src/modules/master-services/service.ts`: `isServiceId(serviceId)`;
`routes.ts`: R11 refuses an unknown `serviceId` with 422
`BUSINESS_RULE_VIOLATION` before inserting, next to the `masterId` check. An
inactive service is not refused: REQ-F-018 deactivates a service for *new
bookings*, and the existing R11 tests do not forbid linking one, so changing
that would be new behaviour.
