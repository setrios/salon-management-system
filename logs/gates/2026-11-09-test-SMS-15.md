## 4. Decisions this gate records

### 4.1 `serviceIds` is CSV in the request and an array in the response

The contract declares the query parameter `type: string` with "Comma-separated
service ids", while `AvailabilityResponse.serviceIds` is an array of uuids. Both
statements are in the approved contract and neither is edited. The tests send
CSV and assert the array echo.

Two outcomes follow from that and are asserted rather than invented:

- a `serviceIds` entry that is not a uuid → **400**, because it is an ill-typed
  query parameter (`error-model.md` §3) and P7 declares 400;
- a well-formed uuid that names no service → **404**, because P7 is in the §3 list
  for 404 and the id names no resource.

### 4.2 M4's `BUSINESS_RULE_VIOLATION` — decision (a): both assertions stand

`error-model.md` §3 lists M4 under `BUSINESS_RULE_VIOLATION` (422), the mirror of
CL-10's problem: a declared response with no declared trigger in words. The
contract's schema accepts `startTime: '18:00', endTime: '10:00'`, and accepts
`startTime === endTime`. Those are the only inputs of M4 that are schema-valid and
semantically broken, so they are what the file asserts.

**Decision: (a), taken by the human on 2026-11-09.** The implementation rejects
both as 422 `BUSINESS_RULE_VIOLATION`; assertions 18–19 stand.

The reasoning, recorded because it draws a line this project will need again:

- **A window that ends before it starts, or has zero length, is self-contradictory
  input.** Under any reading a period that finishes earlier than it begins is not
  a period. There is no alternative semantics to argue about, so the rule can be
  asserted even though no document writes it out.
- **Overlapping windows are the opposite case** (G4): a union, an intersection
  and a rejection are all defensible and no document chooses between them. That
  stays unasserted.
- **The boundary is "self-contradictory" versus "undefined".** A rule derivable
  from what the concept means is assertable; a rule the documents leave open is
  not.

**No CL row.** CL records a contradiction between approved documents. There is
none here — only a rule that was never written down. Applying CL to an unwritten
rule would make the register the wrong place for its own purpose.

### 4.3 Time and time zone — the decision that repeats in S3.2

| Question | Decision here |
|---|---|
| Does S1.3 need an injected clock? | **No.** Every date is a literal; weekly rules name an ISO weekday and date rules name a date, so no rule and no expectation is derived from "today". |
| Does S3.2 need one? | **Yes, and the decision belongs there.** Reminders are "appointment time minus 24 h / 2 h" (REQ-F-010, REQ-F-011), which is relative to now; SMS-11/SMS-17 should inject the clock against their own tests rather than have a mechanism with nothing to inject it into. |
| Which zone interprets `date` and builds slots? | **Europe/Kyiv** — resource-model §3, REQ-NF-007 (one location, one zone; no selector anywhere in the contract). |
| How is the zone made observable? | Two Monday dates, one winter (`+02:00`) and one summer (`+03:00`), with the same wall-clock window. Offsets verified against Node's ICU data before the assertions were written. |

### 4.4 Occupancy is not computed at this stage — one line, stated flatly

**P7 at S1.3 computes slots from availability windows and the requested services'
durations; it does NOT subtract booked appointments, because `appointments` does
not exist until S2.1. `available` is therefore `true` for every slot here.**
Assertion 43 is a statement about the stage, not evidence that a slot is free of
bookings. S2.1 must revisit it. Reading this file as "slots are free" two stages
from now would be reading it wrongly.

### 4.5 The role matrix differs from S1.2, in the other direction

S1.2: a **master** token on `/admin/*` → 403. S1.3: an **administrator** token on
`/me/availability` → 403. Both are JWT-gated and both must refuse the wrong role
with 403 rather than 401 (`error-model.md` §4: 401 is for *no* credentials).
`requireRole('master')` is the first master-side use of the gate; the assertions
5–6 confirm it also *admits* the right role, so a gate that refused everyone
would not pass.
