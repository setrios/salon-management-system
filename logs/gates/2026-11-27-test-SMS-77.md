## 1. The defect

SMS-74's prompt tried to hide the input by replacing readline's internal
`_writeToOutput`. In the promises API of readline on Node 24 that hook is not
what draws the typed characters, so they were echoed — reproduced under a
pseudo-terminal in the agent's container:

```
Password for the administrator: secret-echo-123
create-admin: created the administrator "echo-check" (Echo).
```

The README promises "typing is not shown". A password on the screen ends up in
the scrollback, a screen share or a terminal log — the leak F13 closed for the
shell, reopened by the prompt. SMS-74's tests did not see it: they passed the
password through `ADMIN_PASSWORD`, which never reaches the prompt.

## 2. The test

The prompt runs only on an interactive terminal, so the case runs the script
under `script -qec … /dev/null` (util-linux), types the password and Enter into
the pseudo-terminal, and reads what the terminal showed.

| Case | Asserts | Red run |
|---|---|---|
| P1 | the screen shows the prompt and the confirmation, and **not** the typed password | `expected '…Password for the ad…' not to contain 'typed-secret-4821'` |
| P2 | the account exists with the typed password: A1 signs in, 200 | (reached only after P1) |

Where util-linux's `script` is missing (macOS), the case is skipped with the
reason in its name, not silently passed.

## 3. Planned fix

Read the password without readline's echo: put stdin in raw mode, collect
characters until Enter, handle Backspace and Ctrl-C, write nothing but the
prompt and a newline, restore the terminal mode in every case. The rules of
the password (8–128 characters) are unchanged. The README's quick start
comment states the length rule next to the command, which the developer's run
also showed was missing (`tomi` was refused only after it was typed).

## 3a. SMS-78 — a successful `db:migrate` that looked silent

The same re-run showed `npm run db:migrate` printing nothing after "Using 'pg'
driver for database querying". The developer's diagnosis run: **exit 0, all 13
tables present** — the migration had succeeded (the database already existed
from an earlier run; `docker compose down -v` had not been run). drizzle-kit's
success line `[✓] migrations applied successfully!` is drawn by its spinner
with terminal control codes; under npm 12 on the developer's terminal it did not
appear, while it did when drizzle-kit was run directly. F11's defect was
silence; a success that looks silent leaves the reader exactly where F11 did,
and the README promises a line some terminals will not show.

| Case | Asserts | Red run |
|---|---|---|
| E4 | `npm run db:migrate` prints `db:migrate: the database is up to date.` after a successful run | `expected 'No config path provided, using defaul…' to contain 'db:migrate: the database is up to dat…'` |

Planned fix: the npm script prints that line itself once drizzle-kit has exited
with 0 (`drizzle-kit migrate && node -e …`); a failure keeps drizzle-kit's
non-zero exit and prints no such line. The README's step 2 names this line as
the one to expect. Added to `tests/tooling/first-run.test.ts` as a new case;
E1–E3 and C1–C3 unchanged.
